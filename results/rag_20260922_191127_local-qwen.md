**SIN RAG:**
Los sistemas de conciliación detectan duplicados mediante la aplicación de algoritmos de **identificación única** y **hashing de campos críticos**:

1.  **Claves Primarias:** Comparación de identificadores únicos como referencia de documento (ID) o número de transacción bancaria.
2.  **Firmas Hash:** Generación de checksums combinando los campos más relevantes (Fecha, Monto, Código de Centro de Costo/Cliente) para verificar integridad y unicidad.
3.  **Metadatos de Origen:** Análisis del archivo fuente original (ej. CSV, XML) identificando IDs repetidos antes de la carga (ingreso).
4.  **Fuzzy Matching:** Uso de algoritmos para detectar duplicados causados por discrepancias menores (ej. diferencias de centsimo o formato de fecha), presentándolos para revisión manual.

La base de datos utiliza estructuras de índices (B-Trees o Hash Maps) para realizar estas búsquedas en complejidad O(1) o

**CON RAG:**
Contabilia utiliza una **detección inteligente de duplicados** (Deteccion Inteligente de Duplicados). Detecta específicamente:
- Pagos repetidos.
- Montos ligeramente diferentes.
- Transferencias parecidas con diferentes referencias. [docs/09-PRD-FULL-PLATFORM.md]

Técnicamente, el sistema cruza movimientos contra pagos utilizando **reglas + embeddings** y tiene la capacidad para **aprender de cada confirmación** del usuario para afinar los cruces futuros. [README.md]
